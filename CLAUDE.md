# CLAUDE.md — DSA Mastery

Context for Claude Code working on this repo. Read this first every session.

## What this is

A cross-platform (iOS + Android) DSA learning + tracking app. Not just a
tracker — an authored roadmap, full-depth topic modules, a C++ language primer,
company-tagged interview problems, and progress tooling. Built with Expo +
React Native + TypeScript, backend on Supabase.

Target user: a student grinding DSA for placements/interviews, learning from a
C++ course. The app is the study surface + progress system around that.

## Ground rules

- **Preserve the store's public API.** Screens import from `src/store/progress.ts`.
  When wiring sync (M4), change the implementation, not the shape — actions like
  `setProblemStatus`, `cycleProblemStatus`, `toggleTopic`, `setNote` must keep
  working so the UI doesn't need rewriting.
- **Offline-first is a hard requirement, not a nice-to-have.** Never make the app
  unusable without a network. Content is always bundled; progress caches locally.
- **Never fabricate problem URLs.** Every link in the content was verified. If you
  add problems, verify the URL resolves before committing it. LeetCode uses stable
  `leetcode.com/problems/<slug>/` slugs; GFG uses `geeksforgeeks.org/problems/...`.
- **Keep content multi-language-clean.** The data model separates code by language
  (see `code_snippets` in the schema). Adding Java/Python/JS = adding snippets +
  a primer, never duplicating problems or topics.
- **Secrets never get committed.** `.env` is gitignored. Keys go in `.env` and, for
  builds, in EAS secrets — never hardcoded, never in the repo.
- **Design system is centralized.** All colors/spacing/type live in
  `src/theme/tokens.ts`. Don't hardcode hex values in screens; add a token.
- **Typecheck before calling anything done.** `npx tsc --noEmit` must stay clean,
  and `npm test` (merge + date logic + content freshness) must pass.
- **Dates are local, never UTC.** `new Date().toISOString().slice(0,10)` is a bug
  in this codebase: in IST it files a 2am session under the previous day, which
  breaks streaks and shifts every heatmap square. Use `src/lib/dates.ts`.
- **Progress references content by natural key**, `'<topic slug>::<problem name>'`
  (`problemId()`), never by serial id — the client must be able to record
  progress offline without a lookup round-trip. `scripts/build-content.mjs`
  emits `problems.key` to match; if you change one, change both.

## Design system (dark "paper")

Layered charcoal surfaces (`#0E0E10` bg → `#161618` card → `#1E1E22` raised),
soft ambient shadows, a single red accent (`#E5393B` family) used sparingly.
Type: Archivo (display/heading/body) + JetBrains Mono (code/labels). Signature
element is the GitHub-style contribution heatmap. Full tokens in
`src/theme/tokens.ts`. Reference `/mnt/skills/public/frontend-design` principles
if reworking UI: spend boldness in one place, keep everything else quiet.

## Content pipeline

Source of truth is the per-topic JSON in `src/data/topics/*.json` plus
`src/data/roadmap.json` and `src/data/primer/cpp.json`. These get bundled into
`assets/data/plan.json` (the single file the app imports via `src/lib/content.ts`).
`supabase/seed.sql` is generated from `plan.json`. So the flow is:

```
src/data/*.json  ->  assets/data/plan.json  ->  supabase/seed.sql
```

If you edit content, regenerate the bundle and the seed (a small Python script
did this originally — recreate it or write the equivalent in Node; keep the
"verify every URL" rule). Each topic JSON has: slug, order, title, explainer_md,
patterns_md, complexity_md, code[] (label + C++ code), problems[] (name, url,
platform, difficulty, tier ∈ warmup|core|interview|hard, companies[]).

## Project structure

```
app/                      # Expo Router screens
  _layout.tsx             # root: font loading (Archivo + JetBrains Mono) + splash
  (auth)/                 # sign-in / sign-up / reset (M3)
  (tabs)/
    _layout.tsx           # tab bar: Today / Learn / Practice / Progress / Profile
    index.tsx             # Today — current phase, focus, streak, stats
    learn.tsx             # roadmap + topic list + C++ primer (segmented)
    topic/[slug].tsx      # topic detail — explainer/patterns/complexity/code/problems
    practice.tsx          # full problem list + filters + notes modal
    progress.tsx          # heatmap + difficulty/topic breakdowns
    profile.tsx           # account, sync, language, reminder, github, reset
src/
  theme/tokens.ts         # design system — colors, spacing, radius, type, shadow
  lib/content.ts          # content types + loader + problemId() + allProblems()
  lib/supabase.ts         # client, inert until env keys set (supabaseEnabled)
  lib/auth.ts             # signIn/signUp/signOut/reset + humanized errors
  lib/sync.ts             # push/pull primitives (never throw)
  lib/syncManager.ts      # queue driver — debounce, backoff, flush triggers
  lib/merge.ts            # PURE reconciliation logic (tested)
  lib/dates.ts            # local-day keys + streak decay (tested)
  lib/notifications.ts    # daily reminder scheduling
  lib/remoteContent.ts    # M2 diagnostic — backend vs bundle
  store/progress.ts       # Zustand + AsyncStorage — the store screens depend on
  store/session.ts        # session + localMode gate
  components/ui.tsx        # Card, Pill, Eyebrow, Markdown, CodeBlock, ProgressRing
  components/auth-ui.tsx   # shared auth fields/buttons
  components/Heatmap.tsx   # signature contribution grid
  data/                   # authored source JSON (topics / roadmap / primer)
assets/data/plan.json     # bundled content the app imports
assets/*.png              # generated icon/splash/favicon (npm run icons)
scripts/                  # content pipeline, verifiers, tests, icon generator
supabase/
  schema.sql              # tables + RLS + on-signup trigger
  seed.sql                # content seed (generated from plan.json)
  migrations/             # incremental changes to an already-deployed project
```

## Commands

```bash
npm install               # runs clean with native scripts enabled
npx expo start            # run in Expo Go (scan QR)
npx tsc --noEmit          # typecheck — keep clean
npm test                  # merge + date logic + content freshness

npm run content           # regenerate plan.json + seed.sql from src/data/
npm run icons             # regenerate icon/splash/favicon PNGs
npm run verify:supabase   # deployed content matches the bundle
npm run verify:auth  <email>   # live auth chain (creates throwaway accounts)
npm run verify:sync  <email>   # live sync tables (creates a throwaway account)

npx eas build -p android --profile preview   # APK (needs Expo login + EAS secrets)
```

The `verify:*` scripts hit the real project and create throwaway accounts —
delete them afterwards under Authentication → Users.
